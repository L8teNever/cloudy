Einrichtung bei Cloudflare:
1. Zero Trust → Networks → Tunnels → Tunnel anlegen (z. B. cloudy-pi), den Token (eyJh…) oben einfügen.
2. Beim Tunnel Public Hostname: cloudy.kulbarts.com → Service {{ tn.target }}
3. Access → Applications → Self-hosted für cloudy.kulbarts.com mit Policy (z. B. deine E-Mail), „Mit Cloudflare One Client authentifizieren“ an. Den AUD-Tag der App oben eintragen.
Ohne gültige Anmeldung lässt cloudy über den Tunnel nichts durch – auch wenn die Access-App fehlt. „Mein Gerät“ (/mein) geht nur im Heimnetz.
{% set ld = params.lokal %}

🔐 Eigene Domain nur im Heimnetz (z. B. main.kulbarts.com)

Der Pi beantwortet die Domains im Heimnetz selbst: eine zeigt das ganze Dashboard, die andere nur /mein („Mein Gerät“: VPN an/aus). Das Zertifikat holt er sich bei Let's Encrypt per DNS-Challenge – auf den Geräten muss nichts installiert werden. Von außen ist die Seite nicht erreichbar. Der Token wird nur hier in der Datenbank gespeichert, nicht im Repo.

Zertifikat: {{ ('gültig bis ' ~ ld.cert.expires.strftime('%d.%m.%Y')) if ld.cert else ('noch keins' if (ld.domain or ld.dashboard) else 'nicht eingerichtet') }} {% if ld.status.state %}{{ ld.status.text }}{% endif %}
{% if (ld.domain or ld.dashboard) and ld.has_token %}
{% endif %}
Wichtig: Bei Cloudflare den Tunnel-Hostnamen und den DNS-Eintrag für diese Domain löschen, sonst führt sie von außen weiter zum Tunnel. Geräte mit dem echten WARP-Client (Cloudflare One) fragen Cloudflare statt des Pi – dort wird die Domain nicht aufgelöst; Geräte, die der Pi per VPN/WARP-Container leitet, funktionieren.
